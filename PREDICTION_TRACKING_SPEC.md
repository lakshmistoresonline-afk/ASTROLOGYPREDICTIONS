# PREDICTION TRACKING SPECIFICATION (V1.0)

## 1. OBJECTIVE
To collect high-fidelity calibration data for the Trademind Jyotish Engine without compromising deterministic integrity.

## 2. DATA COLLECTION MODEL
Every prediction generated by the engine must be associated with an immutable snapshot before an outcome can be reported.

### Snapshot Payload
- `predictionId`: UUID
- `domain`: Domain string
- `strength`: Frozen weight result
- `window`: {preparation, build, peak, decline, end}
- `engine_versions`: {calc, dasha, transit, evidence, remedy}

## 3. USER REPORTING INTERFACE
Users are presented with four mutually exclusive outcome options:
1. **OCCURRED**: The predicted event matched the historical reality.
2. **PARTIALLY OCCURRED**: The event themes were present but not fully manifested.
3. **DID NOT OCCUR**: The window passed with no relevant activity.
4. **UNKNOWN**: User is unsure or event is pending.

## 4. TIMING CALIBRATION
If "OCCURRED" is selected, the user is encouraged to provide an `actualEventDate`.
The backend calculates:
- **Exact Match**: ±15 days of predicted Peak.
- **Timing Hit**: ±30 days, ±90 days.
- **Broad Window**: Within the sub-period boundaries.

## 5. REPRODUCIBILITY
Snapshots ensure that even if the engine rules change in V1.1, the V1.0 historical data remains traceable to the exact logic that produced it.
